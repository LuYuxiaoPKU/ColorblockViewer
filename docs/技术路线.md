# 技术路线综述

> 本文档是 v1.0 发布前对**当前 README 的存档**，记录项目的完整技术路线：
> 架构决策、1:1 语义复刻方法论、里程碑演进、验证策略与工程约束。
> 项目简要介绍见根目录 [README.md](../README.md)。

## 1. 项目定位与目标

纯前端静态网站：在浏览器内预览 Minecraft Fabric 模组 **ColorBlock**（原版
CC0 作品，MCBBS 已失；社区维护版仓库名 AnotherColorBlock）
的 `/particleex` 粒子效果，以及**原版** `/particle` 命令（粒子类型表/贴图按
1.21.11 / 26.2 分区，可切换）。用户粘贴命令（或使用结构化表单），浏览器内
3D 渲染粒子生成与逐 tick 动画——无需安装游戏/模组即可调试粒子表达式。

核心目标按优先级：

1. **语义正确性（最高）**：对模组 Java 源码 1:1 语义移植——表达式求值结果、
   粒子生命周期行为、**错误消息文本**都逐字一致；用 golden 测试锁行为。
2. **命令覆盖完整**：模组 10 种 `/particleex` 命令 + `group remove|change` +
   `clearparticle`，以及原版 `/particle` 命令树（逐字核对 `ParticleCommand`）。
3. **可调试性**：表达式实时校验（英文原文 + 中文提示）、命令双向同步表单、
   播放控制（上一帧/下一帧/进度条拖拽回看/倍速/重置）。
4. **零部署成本**：无后端、无构建产物依赖，GitHub Pages 静态托管。

## 2. 技术选型与理由

| 选型 | 理由 |
|---|---|
| React 19 + TypeScript | 结构化表单/面板的组件化；TS 严格模式保证移植层类型安全 |
| Three.js 0.185 + 自定义点云 shader | 粒子是大量小四边形，`THREE.Points` + 自定义 attribute（color/size/uv）最简；加色混合软光晕贴近游戏观感 |
| Vite 8 | 构建快；`base: '/ColorblockViewer/'` 与仓库名一致以适配 GitHub Pages 子路径 |
| Vitest | 与 Vite 同栈；`environment: 'node'` 下引擎/解析/仿真全可测，UI 用 happy-dom |
| `useSyncExternalStore` 轻量外部 store | 命令列表/设置是跨组件共享的"真源"，无需引入状态库 |
| 无后端 | 所有逻辑（表达式引擎、仿真、渲染）纯前端可跑，静态站点即可托管 |

## 3. 1:1 语义移植方法论（本项目最重要的工程决策）

**原则**：预览工具的价值在于"所见即游戏所得"，因此对模组 Java 源码做逐字
语义核对而非行为近似。落地为三层保障：

- **golden 测试**：从 Java 原版跑出的表达式求值结果/报错文本固化为测试向量，
  TS 引擎必须逐字复现（Int32 除法/取模、常量折叠、矩阵函数、函数重载、
  错误消息措辞）。
- **缺陷也复刻**：Java 版的既有缺陷按原样保留而非"顺手修掉"，包括
  - customMove 的 pre/stop 回滚逻辑；
  - `age` 恒 0 的缺陷（导致默认寿命走近似值路径）；
  - 组索引惰性清理；
  - `group change` 遇 do-while 死粒子时 cexe==null 的 NPE → 命令中止（补测锁定）；
  - 浮点定点死循环：`parameter`/`polarparameter` 以 float 推进 begin/end 时
    在 `t+step===t`（量级 ~2^53）处停步无限循环——Java 原版同命令同样冻结
    （2026-09-10 实测确认），按 1:1 原则保留不加熔断。
- **跨版本一致性验证**：对模组 1.21 / 1.21.11 / 26.1 / main 各分支做源码
  diff，确认命令树、参数类型、表达式引擎完全一致（差异仅在权限 API 与
  yarn 改名等渲染侧文件）→ 结论：1:1 移植（基准 1.21.11）对模组支持的
  全部 MC 版本（1.21.1–26.2）语义有效。

**表达式引擎结构**（`src/engine/`）：lexer → parser → AST → 双编译后端
（主：字节码 codegen——同一 AST 经 `new Function` 生成单大闭包、无节点级
调用，2026-09-29 落地；回退：闭包编译后端——逐节点 JS 闭包，`new Function`
不可用（CSP）或生成失败时启用；双后端对拍测试锁数值/错误序列不变）→
runtime + mathfuncs/matrix/struct。
性能门槛：N=20000 sync 31 样本中位 < 15ms（CI runner 噪声抗抖动，见 commit
bbf9f18）；引擎表达式 bench（16ms/tick，2026-09-04 拍板）本地实测：闭包后端
中位 17.77ms 超限 → codegen 后端 14.07ms 通过（约 1.26×，瓶颈在 Math 内建
与 struct 字段访问而非节点级调用；预案预期 3–5× 未达）。

**命令文本格式：brigadier 引号规则**（2026-09-12，用户报告「回显把表达式引号
吃掉」）：模组的表达式/组名参数是 brigadier `string()` —— 未加引号时只有
`0-9 A-Z a-z _ - . +` 合法（`StringReader.isAllowedInUnquotedString`），
遇到 `( ) * ^ & < = , ; ! /` 就**停**，游戏内表现为参数被截断、后续参数错位。
所以规范化输出必须**按需加单引号**（`serialize.fmtStr`：不在字符集内 → `'…'`，
词内 `'` 按 readString 语义写成 `''`；`null`、粒子名等标识符位与数值/坐标位
**不加引号**）。预览的分词刻意保持宽松（未整理的文本直接粘贴也能解析），
但 `src/command/gameFormat.ts` 按参数位逐条**查验游戏内格式**并在 CommandPane
实时显示 ✅/⚠️（含「第 N 个参数含未加引号字符 X → 游戏内会截断」的定位提示），
粘贴→应用后的回显本身即游戏内合法格式（tests/command/gameFormat.test.ts 锁死；
回显与用户游戏内命令逐字一致的回归用例）。

**运行时防护 + 显式提示**（2026-09-10 拍板；「1:1 的是语义，不是后果」）：
① 深嵌套括号——1:1 解析器的 snapshot/recovery 回溯指数爆炸（Java 原版同样
挂死，实测 12 外包层 ~65ms / 16 外包层 ~0.7s / 20 外包层挂死，Probe25 对真实
Java 源码实锤）→ 同时开启括号数 > 13 时中止 + 中文提示（`ParseDepthError`）；
② 浮点步长死循环——conditional 三重扫描 / parameter 的 t 循环 / tick 生成器：
t+step===t 定点不收敛或单命令迭代超 1,000,000（Java 游戏内同输入 = 命令队列
冻结）→ 显式中止 + 提示。预览不复制「冻结」后果，语义层 1:1 不变；bench/测试
表达式仍须浅层平衡树（防护防无限挂死，不改变深层解析性能特征）。

## 4. 架构分层

```
src/
├── engine/    表达式引擎（1:1 移植）：lexer/parser/ast/compiler/runtime/
│              mathfuncs/matrix/struct —— 纯函数，零 DOM 依赖，golden 测试覆盖
├── command/   命令解析：tokens/lexer→parser/schema（brigadier 树逐字核对）/
│              coords（~ 基准坐标）/serialize（结构化数组↔命令文本）
├── sim/       仿真引擎：engine（tick 驱动粒子生命周期）/groups（组管理）/
│              spawn（生成器）/rng（固定种子 PRNG）/structFill
├── render/    渲染层：color（两模式共用的色值/尺寸口径，无 three 依赖）/
│              points（完整模式点云 shader + 贴图图集）/sync（完整模式视口，
│              快照→BufferAttribute）/render2d（快速模式 Canvas 2D 视口，
│              等距投影，不加载 three）/particleData（双版本粒子类型表与贴图映射）
├── store/     appState：useSyncExternalStore 外部 store（commands/设置/HUD/Toast）
├── templates/ library：模板库数据（精编粒子效果模板，命令文本为游戏内合法格式）
└── ui/        面板：CommandPane（命令粘贴框 + 执行/一键清空 + 实时格式检查）
               + Viewport（播放条：播放/上一帧/下一帧/进度条/重置/倍速）
               + SettingsDrawer +
               TemplateGallery（右侧覆盖面板）+ clipboard + StatusToast
```

数据流单向：**粘贴框文本（唯一输入路径）→ 结构化命令数组（唯一真源）
→ 仿真引擎（20 TPS tick）→ 快照 → BufferAttribute → GPU**。文本解析成功后
回写真源并重新序列化对齐；无表单编辑路径（0.2.0 起）。

### 4.1 渲染管线要点

- 点云 shader：顶点 `gl_PointSize = size * uSizeMul * (uScale / -mvPosition.z)`，
  `uScale = h*0.5*min(dpr,2)/tan(fov/2)` 按视口高实时换算（视口 resize 时重算）；
  自定义 attribute 仅 `color`(vec4)/`size`(float)——**position/normal/uv 由
  three 非 raw ShaderMaterial 前缀声明，源码内不得重声明**（重声明 uv 曾致
  顶点着色器 redefinition 编译失败、全浏览器粒子黑屏，已加回归单测锁定）。
- 贴图：官方客户端 jar 提取的粒子图集（`npm run assets <版本>`），12 列 atlas；
  多帧类型走**原版 age-progress 选帧**（帧号 = floor(age·(N-1)/lifetime)，
  随粒子年龄线性推进、全寿命只播一遍不循环）+ 后 50% 寿命线性淡出（死亡瞬间
  alpha=0.5 而非 0）——1.21.1 反编译 `AnimatedParticle.tick` 逐字核对，
  见 §10 证据清单；`block`/`dust`/`item` 等按方块纹理实时渲染的类型
  与未知名回退软发光圆点，按类型微调 size/alpha/色相（TWEAKS 表）。
- 性能：sync 写 BufferAttribute 走快照合并；20 TPS 逻辑由墙钟累加器驱动，
  与 60Hz 渲染解耦。
- **共用色值口径**：color.ts（particleVisual：类型微调 / 多帧白起点 /
  colorFrom→colorTo 插值 / end_rod 0.8^age 颜色靠拢 / ageFade 后半程淡出 /
  shiftHue）——无 three 依赖，完整与快速模式共用，保证同一粒子在两模式下
  色值一致（tests/render/points.test.ts 锁）。

### 4.2 原版 `/particle` 的双版本数据分区

粒子类型注册表与贴图按 **1.21.11（116 类型 / 251 贴图）** 与 **26.2（126 类型 /
285 贴图）** 分区，来源为 Mojang 官方客户端 jar（sha1 校验；注册表经字节码
提取，混淆版 ≤1.21.9 走 javap 标记扫描；data-driven 粒子 JSON 定义帧表）。
设置面板切换版本后，表单下拉与渲染图集同步切换，贴图按版本独立缓存。

### 4.3 渲染模式（完整 WebGL / 快速 Canvas 2D）

`sim.renderMode`（默认 `'full'`，设置抽屉下拉切换）：

- **完整**（现状）：WebGL 点云 + 真实粒子贴图 + 帧动画；three（≈540KB
  gzip 134KB）独立 chunk 动态加载，不阻塞首屏。
- **快速**：Canvas 2D 颜色圆点（render2d.ts）——**不加载 three、无 WebGL**，
  仿真引擎照常 1:1 运行（位置/颜色/寿命全保留），只丢贴图外观。等距正交
  投影（30° 等轴测）+ 每帧按粒子云包围盒自动适配（fit，上限 60px/block，
  无粒子时按网格边长定框）；`globalCompositeOperation='lighter'` 近似 3D 的
  AdditiveBlending，径向渐变软边缘近似圆点着色器的 smoothstep 光晕；
  色值口径与完整模式同一份（§4.1 共用色值口径）；rAF 带脏检查，空闲帧不重绘。
- App 按 renderMode 条件动态 import 两视口（`ViewportApi` 结构兼容，
  deps `[sim.renderMode]`：切换 = 旧视口 dispose + 新视口重建 + 补一次
  初始快照）。纯渲染层设置，引擎不读（mcVersion 先例）；随分享链接 `?s=`
  自动序列化（loadShared 的 sim 合并兼容旧链接）。Canvas 2D 绘制路径依赖
  浏览器上下文，headless 不测像素（§6 验证策略），纯函数 fit/投影有直测
  （tests/render/render2d）。

**首帧预热**（2026-10-04）：首帧两大瓶颈是首帧 render 时的惰性着色器编译
与贴图图集加载。预热侧：图集**并行加载**（`Promise.all` 全帧解码，画布绘制
仍按帧序串行、格布局逐字不变）+ `start()` 内 `renderer.compileAsync` 提前
编译（three 0.185：内部先同步 compile 再 10ms 轮询 `program.isReady()`；
WebGL 上下文不可用时不上 rAF、立即上报 ready 收口，防空转）。可视化侧：
**视口内覆盖进度条**（App 的 `vpProgress` 状态机 + `vp-progress` 覆盖层）——
三段：import（three chunk 加载中，indeterminate）/ atlas（0.10–0.90，
`frac = 0.1 + drew/total*0.8`）/ compile（atlas 完成后 label 切「编译着色器…」），
`ready` →「就绪」400ms 淡出卸载。进度只在首帧上报：视口级 `readyReported`
是权威门控（App 的 readyRef 在模式切换重挂视口时会复位，靠不住）——ready
后版本切换触发的新图集加载不再重弹进度条。

### 4.4 链接参数与模板库

- `?s=<base64url>`：**完整场景**（命令列表 + 设置）——启动时经
  `share/bootstrap.applySharedSearch` 还原（载荷损坏 → toast，不动默认场景）。
  0.2.0 起前端不再提供生成入口（「🔗 复制分享链接」按钮已删），解码能力保留。
- `?t=<模板 id>`：**模板直达**（只带模板命令，设置保持当前值）。0.2.0 起前端
  不再提供生成入口（模板卡片「🔗 复制链接」按钮已删），解码能力保留。
  两者同时出现时 `?s=` 优先。
- **模板库交互位置**（2026-09-12 定稿）：入口在命令区（「执行」同一区块的按钮行，
  与「🗑 一键清空」并列），打开**右侧覆盖面板**（宽 `min(680px, 92vw)`；窄窗
  ≤900px 全宽、卡片单列；Esc / 点遮罩关闭），画布在左侧保持可见，便于
  「载入并执行」边看边试。曾试过「常驻精选 chips + 空状态从模板开始引导」，
  因占位与按钮重复已移除（模板入口统一走面板）。模板数据与质量闸门见 §6。
- **「🗑 一键清空」**：清空命令真源（`replaceCommands([])` → 粘贴框文本自动变空、
  命令列表清空）+ 回放重置（清掉画面粒子/生成器/tick），toast 说明后续可粘贴或从
  模板库载入。
- 模板卡片每卡两个按钮：**「📋 复制命令」**= 游戏内可直接粘贴的文本；
  **「载入并执行」= 清空重来** —— 先 `replaceCommands` 替换命令真源，
  再走 App 的 `runFresh`（引擎**回放重置**：清粒子/组/生成器/tick/PRNG → 清 toast →
  按新命令执行），因此不会叠加旧命令与旧粒子。

## 6. 验证策略

- **1147 个测试**：引擎 golden / 命令解析（含 SNBT 数字字面量语义锁：
  hex 无后缀 = INT 无符号位模式 0x80000000 → -2147483648、I 后缀 = 有符号
  parseInt 位模式（0x80000000I = -2147483648 放行、>0xFFFFFFFF 拒）、
  B/S/I/L 位宽上界（hex/二进制 I：parseUnsignedInt 域；十进制 B/S/I/L：
  SIGNED 解析域 ±127/±32767/±2^31-1，越界游戏拒——2026-10-04 tests/nbt
  直测驱动收紧）、二进制字面量 0b101（BINARY base → UNSIGNED INT 位模式）、
  十进制纯整数前导零拒绝（0123 拒 / 0123.4 放行，float 路径无此检查；
  0_5 同样拒——0 消费后 run 首字符为数字/下划线皆拒、marker 只吃裸 0
  成 trailing data）、
  数字运行首/尾下划线拒绝（连续下划线允许，1_0_0 / 1__0 放行，
  十/十六/二进制统一，2026-10-04 十进制同步）/

  平铺帧**（9 组 typed 数组，Transferable 零拷贝）上行，两渲染模式经
  `frameToParticles` 还原后走同一份渲染路径；基础设施已就绪
  （`src/worker/simWorker.ts` 纯仿真 worker / `client.ts` SimClient +
  平铺帧协议 / App 双路径接线 + worker 构造/崩溃降级主线程 +
  `updateParts` 视口入口），探针实测 **1M flame 稳态**（1M 粒子每 tick
  全池演进 + 降频 k=5）：A 主线程全成本 116.8ms/tick
  （tick 31 + 时间线 22 + snapshot 15 + fill 48）；B worker 侧 255.1ms
  （tick + 时间线 + snapshot + **toFlatFrame 177ms**——9 组 typed 数组
  逐粒子填充 + 上行序列化；平铺侧份额 ≈ 187ms，= 主线程侧 C 全量
  126ms 的 1.5×、主线程渲染计算本身 38ms 的 4.7×）；C 主线程侧 126.2ms
  （frameToParticles 71ms——1M 对象重建，+ fill 38ms）；
  max(B,C)/A = 218% → 并行收益 -118%（落地条件 max(B,C) < A×0.95 远
  未达标）。结构性结论：每帧必须把 1M 粒子全量搬运一次，**平铺/还原
  的序列化成本 ≥ 主线程渲染计算本身**，「平铺帧上行」形态下并行
  抵消不了搬运。若未来重启 worker 化，须绕开平铺帧：worker 侧直接
  产出渲染 buffer（fillParticleBuffers 同口径，4 组 typed 数组
  12N float ≈ 48MB/帧，上行量减半且免对象重建）或直接上行 SoA 引擎
  缓冲（需引擎侧改造，1:1 风险面）——两者均须重新实测。

## 7. 预览简化清单（与游戏内的已知差异）

- **贴图近似**：颜色乘法着色、统一加色混合；`block`/`dust`/`item` 等按方块
  纹理实时渲染的类型与未知名回退软发光圆点。帧动画与淡出已按原版
  age-progress 语义复刻（§4.1 / §10），不再是全局相位循环。
- **颜色 float 量化**：模组字节码颜色全程 float 字段（spawn payload `FFF F`、
  表达式回写经 `d2f` 截回），预览侧解析到回写全程 double 未做 `Math.fround`
  量化——可观测偏差 ≤ ~1e-7，不影响 1:1 数值语义的可复现性（同命令同种子
  轨迹一致），仅严格「逐字节码」口径下的已知近似（2026-09-10 拍板：维持
  近似，不引入 fround）。
- **粒子渲染上限**：点云缓冲在挂载时按当时 maxParticles 预分配（运行期调大
  上限不扩容缓冲），活粒子数超过容量时超出部分不渲染；HUD 在「粒子 N」后
  显示「渲染截断」提示（2026-09-10 拍板：从静默截断改为显式提示，引擎侧
  丢弃计数不变）。默认上限 1000000（2026-10-05，用户拍板）：完整模式点云
  缓冲预分配 1M 顶点（pos 3/color 4/size 1/uv 2 ≈ 40MB GPU 内存）。
- **播放时间线**（2026-10-05，`sim/timeline.ts`）：播放循环记录场景快照
  （tick + 活粒子 + 丢弃计数 + 末帧标记），**大场景自动降频**（2026-10-09
  用户拍板）：单帧拷贝成本与粒子数成正比（1M flame 实测 ~54ms/tick），
  大场景逐 tick 记录的拷贝很快被丢、成本白花——count ≤ 1 万逐 tick 记录
  （常规命令行为不变）；count > 1 万按**成本封顶** k = ⌈count/20 万⌉ 每 k
  tick 记一帧（每 tick 记录成本 ≤ ~10ms：1M 满帧 k=5，54ms → ~11ms），末帧
  恒记录。代价：大场景 seek 粒度从逐 tick 变逐 k tick（帧 tick 仍严格
  递增，findFrame 二分不变）。内存预算 = **1M 总粒子
  拷贝**（JS 对象实测 ~400B/份 ≈ 400MB），按每帧**实际**粒子数累计，超预算
  从头部**丢最旧帧**（最旧即最早经过的状态，价值最低；与粒子上限解耦）——
  小场景（12 粒子）可回放 ~8 万帧（≈70 分钟），1M 满帧场景只容 1 帧（大场景
  回放只覆盖最后时刻，拖条前段为空是如实行为）。进度条右端 = **预估总
  时长**（2026-10-05 改口径：命令可预估总时长取代旧口径「末帧 tick + 剩余
  预算可录帧数」——生成器命令录不满时右端不再留大空白）：每条命令的时长
  = 寿命上界（age>0 取 age；age=-1 永活；age=0 按原版运动学寿命公式的**最
  不利随机数**上界，未建模类型回退默认寿命）+ tick 变体的生成期（⌊(end−
  begin)/step⌋+1 个 t 值 ÷ cpt 向上取整），执行点起算、多命令取 max 防叠加
  压缩（`parser.estimateDuration`）；引擎记录生成器引用（`lastGenerators`，
  g.t 原地推进），生成中再按最后一个生成器的剩余 t→end ÷ cpt 校正
  （`App.calcMaxTick`）。播放超出预估（末帧已越过右端）时退化为末帧 tick
  （右端不再外扩）；拖到已记录范围之外 clamp 到末帧。命令执行即记录初始
  帧（tick 0 快照），未播放时进度条即可拖动（回到初始状态），不必等播放
  开始。seek 回放按帧的
  粒子列表从**当前活池**取回真粒子对象（渲染只读 13 字段都在真对象上），
  已死粒子用帧内浅拷贝——拷贝缺运动学字段（gf/ff 等）不影响显示；续播时
  拷贝粒子按缺省（无衰减/无自定义曲线）演进，文档化近似。trail/vibration
  是增量式 lerp（每 tick 基于本 tick 起点推进），seek 后活池真粒子须按目标
  帧 age 用闭式解 x(a) = c* + (target−c*)·a/(lifetime−1) 回退到历史位置
  （`timeline.rewindLiveParticles`；帧拷贝的 x 本就是历史值不动），否则画面
  不随拖动/上下帧回退。回看帧的粒子列表里，已死粒子（末帧起活池已清空）的
  帧拷贝 alive 仍为 false，而 engine.snapshot 按 alive 过滤 → 若不把回看的
  resolved 粒子统一复活（p.alive = true），渲染层拿到空列表：HUD 计数有值、
  画面空（「回拉进度条粒子不复现」）。播放到末帧
  （寿命全部结束）自动停止并停在最后一帧（不再推「已自动停止」toast），
  时间线保留可拖条/◀▶ 回看。画布控制条「▶ 播放 / ⏸ 暂停」按钮：播放中 =
  暂停；停在末帧（末帧有 end 标记且播放头在末帧）= 从头重跑（playFresh：
  重置 + 重新执行命令 + 从头播放，tick 归零、粒子重新生成——播放循环末帧
  那步引擎 tick 已 ++ 到 endTick+1，直接续播会「往前走 1 tick」且画面为空）；
  其余（未执行过命令 / 中途暂停 / 回看中）= 继续播放。
- **原版 `type{NBT}`**：14 个扁平标量类型（16 个类型名）的 NBT 载荷按各自
