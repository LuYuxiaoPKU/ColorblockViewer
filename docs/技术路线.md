## 1. 项目定位与目标

纯前端静态网站：在浏览器内预览 Minecraft Fabric 模组 **AnotherColorBlock**
的 `/particleex` 粒子效果，以及**原版** `/particle` 命令（粒子类型表/贴图按
1.21.11 / 26.2 分区，可切换）。用户粘贴命令（或使用结构化表单），浏览器内
3D 渲染粒子生成与逐 tick 动画——无需安装游戏/模组即可调试粒子表达式。

核心目标按优先级：

1. **语义正确性（最高）**：对模组 Java 源码 1:1 语义移植——表达式求值结果、
   粒子生命周期行为、**错误消息文本**都逐字一致；用 golden 测试锁行为。
2. **命令覆盖完整**：模组 10 种 `/particleex` 命令 + `group remove|change` +
   `clearparticle`，以及原版 `/particle` 命令树（逐字核对 `ParticleCommand`）。
3. **可调试性**：表达式实时校验（英文原文 + 中文提示）、命令双向同步表单、
   播放控制（单步/倍速/重置）。
4. **零部署成本**：无后端、无构建产物依赖，GitHub Pages 静态托管。

## 2. 技术选型与理由

| 选型 | 理由 |
|---|---|
| React 19 + TypeScript | 结构化表单/面板的组件化；TS 严格模式保证移植层类型安全 |
| Three.js 0.185 + 自定义点云 shader | 粒子是大量小四边形，`THREE.Points` + 自定义 attribute（color/size/uv）最简；加色混合软光晕贴近游戏观感 |
| Vite 8 | 构建快；`base: '/ColorblockViewer/'` 与仓库名一致以适配 GitHub Pages 子路径 |
| Vitest | 与 Vite 同栈；`environment: 'node'` 下引擎/解析/仿真全可测，UI 用 happy-dom |
| `useSyncExternalStore` 轻量外部 store | 命令列表/设置是跨组件共享的"真源"，无需引入状态库 |
| 无后端 | 所有逻辑（表达式引擎、仿真、渲染）纯前端可跑，静态站点即可托管 |

## 3. 1:1 语义移植方法论（本项目最重要的工程决策）

**原则**：预览工具的价值在于"所见即游戏所得"，因此对模组 Java 源码做逐字
语义核对而非行为近似。落地为三层保障：

- **golden 测试**：从 Java 原版跑出的表达式求值结果/报错文本固化为测试向量，
  TS 引擎必须逐字复现（Int32 除法/取模、常量折叠、矩阵函数、函数重载、
  错误消息措辞）。
- **缺陷也复刻**：Java 版的既有缺陷按原样保留而非"顺手修掉"，包括
  - customMove 的 pre/stop 回滚逻辑；
  - `age` 恒 0 的缺陷（导致默认寿命走近似值路径）；
  - 组索引惰性清理；
  - `group change` 遇 do-while 死粒子时 cexe==null 的 NPE → 命令中止（补测锁定）；
  - 浮点定点死循环：`parameter`/`polarparameter` 以 float 推进 begin/end 时
    在 `t+step===t`（量级 ~2^53）处停步无限循环——Java 原版同命令同样冻结
    （2026-09-10 实测确认），按 1:1 原则保留不加熔断。
- **跨版本一致性验证**：对模组 1.21 / 1.21.11 / 26.1 / main 各分支做源码
  diff，确认命令树、参数类型、表达式引擎完全一致（差异仅在权限 API 与
  yarn 改名等渲染侧文件）→ 结论：1:1 移植（基准 1.21.11）对模组支持的
  全部 MC 版本（1.21.1–26.2）语义有效。

**表达式引擎结构**（`src/engine/`）：lexer → parser → AST → compiler
（闭包编译后端，表达式编译为 JS 闭包）→ runtime + mathfuncs/matrix/struct。
性能门槛：N=20000 sync 31 样本中位 < 15ms（CI runner 噪声抗抖动，见 commit
bbf9f18）；字节码保险丝触发条件 >25ms/tick。

**运行时防护 + 显式提示**（2026-09-10 拍板；「1:1 的是语义，不是后果」）：
① 深嵌套括号——1:1 解析器的 snapshot/recovery 回溯指数爆炸（Java 原版同样
挂死，实测 12 外包层 ~65ms / 16 外包层 ~0.7s / 20 外包层挂死，Probe25 对真实
Java 源码实锤）→ 同时开启括号数 > 13 时中止 + 中文提示（`ParseDepthError`）；
② 浮点步长死循环——conditional 三重扫描 / parameter 的 t 循环 / tick 生成器：
t+step===t 定点不收敛或单命令迭代超 1,000,000（Java 游戏内同输入 = 命令队列
冻结）→ 显式中止 + 提示。预览不复制「冻结」后果，语义层 1:1 不变；bench/测试
表达式仍须浅层平衡树（防护防无限挂死，不改变深层解析性能特征）。

## 4. 架构分层

```
src/
├── engine/    表达式引擎（1:1 移植）：lexer/parser/ast/compiler/runtime/
│              mathfuncs/matrix/struct —— 纯函数，零 DOM 依赖，golden 测试覆盖
├── command/   命令解析：tokens/lexer→parser/schema（brigadier 树逐字核对）/
│              coords（~ 基准坐标）/serialize（结构化数组↔命令文本）
├── sim/       仿真引擎：engine（tick 驱动粒子生命周期）/groups（组管理）/
│              spawn（生成器）/rng（固定种子 PRNG）/structFill
├── render/    Three.js 渲染：scene（相机/网格/装配）/points（点云 shader +
│              贴图图集）/sync（快照→BufferAttribute）/particleData
│              （双版本粒子类型表与贴图映射）
├── store/     appState：useSyncExternalStore 外部 store（commands/设置/HUD/Toast）
└── ui/        面板：CommandPane + CommandForm（双向同步）+ ExprField
               （防抖编译校验 + 语法高亮）+ Viewport + SettingsDrawer + StatusToast
```

数据流单向：**文本/表单 → 结构化命令数组（唯一真源）→ 仿真引擎（20 TPS tick）
→ 快照 → BufferAttribute → GPU**。表单与命令文本双向同步，改任一侧都归一到
真源再渲染另一侧。

### 4.1 渲染管线要点

- 点云 shader：顶点 `gl_PointSize = size * uSizeMul * (uScale / -mvPosition.z)`，
  `uScale = h*0.5*min(dpr,2)/tan(fov/2)` 按视口高实时换算（视口 resize 时重算）；
  自定义 attribute 仅 `color`(vec4)/`size`(float)——**position/normal/uv 由
  three 非 raw ShaderMaterial 前缀声明，源码内不得重声明**（重声明 uv 曾致
  顶点着色器 redefinition 编译失败、全浏览器粒子黑屏，已加回归单测锁定）。
- 贴图：官方客户端 jar 提取的粒子图集（`npm run assets <版本>`），12 列 atlas；
  多帧类型走**原版 age-progress 选帧**（帧号 = floor(age·(N-1)/lifetime)，
  随粒子年龄线性推进、全寿命只播一遍不循环）+ 后 50% 寿命线性淡出（死亡瞬间
  alpha=0.5 而非 0）——1.21.1 反编译 `AnimatedParticle.tick` 逐字核对，
  见 §10 证据清单；`block`/`dust`/`item` 等按方块纹理实时渲染的类型
  与未知名回退软发光圆点，按类型微调 size/alpha/色相（TWEAKS 表）。
- 性能：sync 写 BufferAttribute 走快照合并；20 TPS 逻辑由墙钟累加器驱动，
  与 60Hz 渲染解耦。

### 4.2 原版 `/particle` 的双版本数据分区

粒子类型注册表与贴图按 **1.21.11（116 类型 / 251 贴图）** 与 **26.2（126 类型 /
285 贴图）** 分区，来源为 Mojang 官方客户端 jar（sha1 校验；注册表经字节码
提取，混淆版 ≤1.21.9 走 javap 标记扫描；data-driven 粒子 JSON 定义帧表）。
设置面板切换版本后，表单下拉与渲染图集同步切换，贴图按版本独立缓存。

## 6. 验证策略

- **853 个测试**：引擎 golden / 命令解析 / 仿真生命周期（含全 2^24 域寿命
  直方图对拍 + NATIVE_KINEMATICS 表值 f2d 加宽精确值防回归）/ 渲染 / UI 集成，
  `npm test` 全量跑。
- **CI**（GitHub Actions，push main 触发）：`npm ci → npm test → vite build
  （tsc --noEmit 内置于 build 脚本；曾另设独立 tsc 步骤，2026-09-10 去重）
  → base 前缀断言 → Pages 部署`；任何一步失败不部署。
- **headless 浏览器探针**：chrome `--headless=new --dump-dom` 注入探针读
  canvas 尺寸/uScale/`renderer.info`，验证布局与渲染管线（注意：
  `--window-size` 的有效窗口不保证等于 flag 值；`renderer.info.render.*`
  只计 draw 尝试，program 无效时也计数，探针必须同时抓 `console.error`
  才能发现 shader 编译失败这类致命错误）。
- **性能门槛**：N=20000 sync 中位 < 15ms（31 样本抗抖动；门槛按 CI runner
  实际 CPU 历 2ms → 5ms → 15ms 三档调整，cc47833/bbf9f18）；引擎表达式 bench
  （engine/bench.ts）为报告型——16ms/tick 门槛与 >25ms/tick 字节码保险丝
  仅输出 ✅/❌、不 gate CI（2026-09-10 拍板：保持报告型；本地中位 16.91ms
  已超 16ms，加断言会直接红 CI）。

## 7. 预览简化清单（与游戏内的已知差异）

- **贴图近似**：颜色乘法着色、统一加色混合；`block`/`dust`/`item` 等按方块
  纹理实时渲染的类型与未知名回退软发光圆点。帧动画与淡出已按原版
  age-progress 语义复刻（§4.1 / §10），不再是全局相位循环。
- **颜色 float 量化**：模组字节码颜色全程 float 字段（spawn payload `FFF F`、
  表达式回写经 `d2f` 截回），预览侧解析到回写全程 double 未做 `Math.fround`
  量化——可观测偏差 ≤ ~1e-7，不影响 1:1 数值语义的可复现性（同命令同种子
  轨迹一致），仅严格「逐字节码」口径下的已知近似（2026-09-10 拍板：维持
  近似，不引入 fround）。
- **粒子渲染上限**：点云缓冲在挂载时按当时 maxParticles 预分配（运行期调大
  上限不扩容缓冲），活粒子数超过容量时超出部分不渲染；HUD 在「粒子 N」后
  显示「渲染截断」提示（2026-09-10 拍板：从静默截断改为显式提示，引擎侧
  丢弃计数不变）。
- **原版 `type{NBT}`**：14 个扁平标量类型（16 个类型名）的 NBT 载荷按各自
  ParticleOptions CODEC 逐字段校验并消费渲染色/大小倍数（schema 表
  `nbt/particleOptions.ts`：dust/dust_color_transition 的 color+scale、
  effect/instant_effect 的 color+power、entity_effect/tinted_leaves/flash 的
  ARGB color、dragon_breath 的 power、sculk_charge 的 roll、shriek 的 delay、
  geyser 系 4 的 water_blocks+burst_impulse_base，仅 26.2）。字段 codec
  取证 = 26.2 命名版逐类 javap 字节码（fieldOf/optionalFieldOf 必填性与
  缺省值、RGB/ARGB/SCALE/POSITIVE_INT 各 CODEC；1.21.11 混淆版同构核对）。
  已知近似：DustParticle 的逐粒子 ±20% 颜色抖动（randomizeColor）不做；
  dust_color_transition 的 age 颜色插值不模拟（取 from_color 出生色）；
  power/roll/delay/burst_impulse_base 不影响可见外观 → 不消费。
  嵌套 8 类（block/block_marker/block_crumble/falling_dust/dust_pillar/item/
  vibration/trail）已按 26.2 CODEC 逐字段校验（2026-09-10）：block 系 5 类 =
  BlockParticleOption（block_state = BlockState.CODEC dispatch("Name")，map
  须含 Name 字符串或 SNBT 字符串块名，Properties 不深校验）；item =
  ItemStackTemplate（id 必填/count 1-99/components 无界放行）；trail =
  target(Vec3 恰 3 数值)+color(RGB)+duration(POSITIVE_INT)；vibration =
  destination(SAFE_POSITION_SOURCE：{block:{pos:[3 整数]}}，entity → "Entity
  position sources are not allowed")+arrival_in_ticks(INT)。消费：trail 的
  color 渲染色、target 每 tick lerp 回位（Mth.lerp(f2,x,target) =
  x+(target−x)·1/(lifetime−age)，位置线性推进、末 tick 恰好落点；JDK21
  ProbeTrail 逐位 golden 锁轨迹）、duration 寿命覆写（优先级 命令 age >
  duration > 公式）；vibration 的 destination block 中心（+0.5 各轴）每 tick
  lerp 推进至波源（同型公式、target = 方块中心；JDK21 ProbeVibration 逐位
  golden 锁轨迹）、arrival_in_ticks 寿命覆写（构造器参数直传，同优先级）；
  block_state/item 渲染不消费（贴图/波源近似，见 §10 近似清单）。
  SNBT 侧支持：嵌套 compound 值、裸 key 含命名空间冒号（minecraft:food，取
  最后顶层冒号分隔）、注册表 ID 裸写字符串可作值（SNBT unquotedString：
  stone/stick 合法，数字开头/含引号括号者须引号）。
- **原版命令寿命**：`kinematics.ts` 表内类型（26.2 共 108 个，见 §10）走原版
  随机/常量寿命公式（JDK 探针逐值对拍）；表外类型无逐类型数据 → 统一走
  「默认寿命」近似值。「原版运动学」设置关闭时全部走近似值。
- **原版 force/viewers 槽位**：与预览无关 → 解析层明确报错（而非静默忽略）。
- **运动学**：默认「原版运动学」开启，表内类型按 26.2 字节码逐字复刻摩擦/
  重力/运动模式（base 管道、portal 绝对位置式、reverse_portal 增量式、
  vibration 绝对式 lerp 归位）、重力后置 + 终端速度钳制（falling_dust
  gravityPost/terminalVy）、campfire 出生初速与构造器出生初速修正
  （spawnVelocityMul/spawnVelOffsetY，见 §10）；**表外类型仍走
  匀速直线**（approx 清单：发射器/实体跟随/世界状态依赖类型，见 §10 未建模
  清单）。该设置可关闭回退全类型匀速直线。
- **随机序列**：`normal` 高斯偏移与原版 delta/speed 用固定种子 PRNG；原版
  粒子随机寿命用独立 PRNG（seed+1），同一 `vanillaRand` 同时供应各类型的
  寿命公式随机量（campfire 另消费出生初速 float，顺序与构造器字节码一致）。
  均保证同一次预览可复现，不逐粒子对齐游戏内 Java `Random` 实例序列
  （原版逐粒子 `RandomSource.create()` 种子不可复现）。
